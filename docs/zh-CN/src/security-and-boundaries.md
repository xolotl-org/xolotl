# 安全边界

## 信任边界与密码政策

本文维护发布前安全政策，要求不代表所有部署或协议已通过互操作验收或独立安全审查。先确定保护对象与攻击者，再选择控制；crate、函数或队列不自动构成密码边界。

Core、Kernel 和可信 Driver 通过移动或合理共享传递普通类型化值，保留身份、Handle 归属、权限、来源和预算核验，不逐层加解密、签名或序列化。恶意原生代码的隔离由进程或沙箱提供，内部加密不保护同进程使用的明文。传输端点终止受保护信道，凭据／存储拥有者在写入和读取边界密封私有秘密；不信任中继的应用拥有端到端内容加密。这些控制保护不同对象，各自维护密钥生命周期，静态密封不扩散为 Value 表示。

| 边界 | 发布前默认政策 |
| --- | --- |
| 远程 TLS | TLS 1.3、`X25519MLKEM768` 混合交换、AES-256-GCM 或 ChaCha20-Poly1305；拒绝经典回退与业务 0-RTT |
| 节点／自有公钥身份 | ML-DSA-65；限定用途、受众、有效期和规范编码权威链，将证明绑定到已验证信道 |
| 口令／TOTP／bearer／配对 | 有界 Argon2id、高熵 HMAC 秘密、OS 生成的 256 位 bearer 与配对材料 |
| External 包络 | 256 位 PSK 派生的 ChaCha20-Poly1305；远程会话同时要求 TLS，防止记录流量后静态 PSK 泄漏 |
| 本地秘密 | 私有凭据拥有者维护完整性、对象／版本绑定与提交语义；宿主保护密钥、权限、备份和恢复锚点 |

采用成熟算法实现与标准组合。交换与认证分别报告，已验证节点不继承用户权限。报告实际交换、认证路径、内容可见方、静态保护及证据，不使用单一「后量子安全」标志。PQC 不修复弱口令、恶意宿主、越权、回滚或明文泄漏。

daemon gRPC 监听器与标准 fetch／推理 HTTPS 客户端分别显式选择 TLS provider，不依赖进程默认值。HTTPS 客户端保留平台信任验证，同时要求 ML-DSA-65 认证与远程 TLS 政策；不兼容的第三方服务直接拒绝，不回退到经典算法。这些客户端禁用会话恢复与早期数据；宿主无需安装全局 crypto provider。

适配器从已完成握手提供实际版本、交换组、已验证对端和信道绑定；请求头、Hello 和 feature 不是握手证据。身份拥有者验证根、在线授权、用途、期限与信道证明；用户／服务主体独立验证签发方、受众与持有者。服务再检查当前资源、动作、范围和限额，在合同要求的分派、提交和交付点复核。Kernel 接收已验证的本地身份与权限，不解析网络证明。拒绝缺失证据、不可验证授权、过期和降级，不自动重试为明文或经典算法。

只向下一层传递最小已验证事实，缓存隔离遵循主体与可见范围。不可信输入在昂贵工作前接受长度、深度、并发、期限、KDF／验签与队列预算；成功认证不解除限制。本地 SDK 无需 TLS，回环或 OS 保护的 IPC 可使用本地边界；LAN、公网或代理由实际终止端满足远程政策。「可信代理」设置不能证明上游混合交换或后量子身份。经典 Passkey 保留认证器／浏览器保证，不能报告为后量子；口令、TOTP 的限速、MFA、恢复与撤销独立生效。

根、TLS、会话票据、bearer 和内容密钥独立轮换。新算法需要版本化政策和独立互操作证据；根泄漏恢复需要独立可信锚点或重新批准。加密与清零不证明防回滚，也不保证副本、旧页、转储和备份擦除。停止新工作或交付时，已接纳效果保留实际标识供对账。

发布验收覆盖实际协商、正确／错误证明、降级与重放拒绝、撤销竞态、篡改与错误绑定、预算耗尽、恢复／旧备份和秘密泄漏。标准库及单元测试不等于独立安全审查，只报告已检查保证；Console 与配对记录密封不代表通用 State、对象或备份已加密。

Xolotl 分别在授权编译、操作分派、服务准入和传输边界检查权限。

## 授权

授权范围从 `Grant` 开始，在派生或请求准入时衰减，并由 `open()` 编译成某个进程持有的 `Handle`。数据路径在分派前检查句柄所有者、存活状态、方法权限和剩余策略。

`state://kernel/*`、`state://vault/*` 和 `state://fact/*` 等保留前缀不属于通用应用 State。kernel 和 vault 状态由各自所有者及专用管理动作维护，fact 路径提供只读视图；宽泛的 State grant 不能将它们变成普通可写数据。控制台管理动作使用固定描述符，并按具体路径准入。

选择 Gateway retry epoch 不授予账户或 surface 权限。关闭范围是可信宿主操作，不是客户端 RPC，也不授权重发未知效果。Source 证据检查仍须核验当前 Console 权限、MFA、具体目标、理由及最终交付权限；观察审计归该披露边界，Source 查询只读，不增加私有审计提交。没有留存证据不证明未提交，也不授权释放责任或重放。领域规则归[Gateway 请求存储](https://github.com/xolotl-org/xolotl/blob/main/crates/xolotl-gateway/src/idempotency_store.rs)和[Source 检查](https://github.com/xolotl-org/xolotl/blob/main/crates/xolotl-source/src/lib.rs)合同维护。

## 来源链与污点

值通过 `TaintSet` 携带来源链。污点来源包括作者常量、模型输出、由网关、Source 和 Provider 边界准入的入站 payload、抓取内容和受保护来源。操作输入会把污点传播到输出；状态存储 `TaintedValue`，因此来源链会跨状态写入和读取保留。

策略可以基于来源链做决定。例如，如果出站操作的输入来源链接触过受保护来源，该操作可以被拒绝。

## 敏感值

普通执行操作、应用 State、Fact 和 trace 只保留敏感值的引用或脱敏元数据。专用 Console vault 行按有界访问和条件写入保存凭据验证材料，包括 TOTP secret；见[凭据存储](console-http-and-credentials.md#第二因子与凭据生命周期)。

Console 凭据 vault 行与独立的外部配对凭据文件分别使用宿主提供的 AES-256-GCM-SIV 密钥加密；旧明文、缺失或错误密钥、被修改的密文均拒绝读取。宿主须保护密钥和备份，包括可能保留旧明文的 redb 写时复制物理页；TLS 不保护磁盘数据。联邦 Session 将后量子节点证明以及使用托管主体时的主体证明绑定到完整握手的混合 TLS；整个系统尚未经过独立的端到端安全审查。见[联邦安全契约](security-and-boundaries.md)。

宿主显式安装观察存储时，控制台认证写入脱敏后的网关审计事实记录；安装后的记录错误仍向调用者传播。配对原始敏感值在配对驱动内生成，只通过一次性展示边界离开；记录的操作只携带哈希/校验和元数据。控制台协议声明了敏感值托管动作，但控制台宿主会阻止原始敏感值显示；已安装观察存储时记录这次尝试，安装后错误继续传播。必需的记录屏障仍使用严格 API。

## 控制台边界

Rust 宿主、HTTP 单次调用和 Console WebSocket 共享认证管理入口；Rust 和 WebSocket 通过 `ConsoleService::subscribe` 共用订阅准入与生命周期，WebSocket 负责帧交付。客户端提交描述符命名的动作，分发前执行输入 schema 和 step-up 检查，领域处理器按具体目标授权。

管理动作按所属合同检查授权、状态、CAS、可见性及运行时操作；观察记录由宿主显式安装，不能代替必需的业务提交屏障。受保护载荷视图需要显式可见性元数据，例如 scope、justification 和 TTL。

level 2 要求独立第二证明或通过用户验证的 Passkey；密码复核和注册确认不提供这类证明。会话保存实际验证的主、第二证明及时间，等级和近期时间由证据派生，refresh 不延长认证时间或绝对期限。TOTP 防重放、恢复码消费和因素绑定使用 vault 聚合记录 CAS。外部 MFA Provider 由可信宿主安装，并负责其证明的独立性、时效与防重放。具体生命周期见[Console 第二因子契约](console-http-and-credentials.md#第二因子与凭据生命周期)。

管理动作完成当前权限、状态及输入核验后执行，直接返回实际结果，不再为修改审计另写开始／完成记录。执行失败或取消仍不代表回滚；运行请求保留当前任务的取消与句柄清理责任。

`details.authentication` 描述已准入请求的会话或新签发会话，不表示每个动作都重新认证。内核保留应用审计详情，但不把它解释为权限。可信写入方负责来源与脱敏；审计字段和失败处理见[修改结果](console-actions-and-streams.md#修改结果)。

## 驱动边界

标准终端驱动直接执行 argv，从不通过 shell，受 Kernel 权限与宿主命令允许／拒绝列表约束。调用者提供的 `approved` 标志和 `high_risk` 命令分类不是认证或审批证据；标准驱动不接受这些伪审批控制，人工审批政策归应用。清理只覆盖直接子进程，不提供整个操作系统进程树的隔离或终止保证。宿主责任与限额见[终端安装](api-reference.md#终端安装)。

标准 Fetch 仅访问公开网络：只接纳 HTTP(S) URL，拒绝本地／内部名称及非公开 IP 字面量，并在连接前验证实际连接器使用的 DNS 地址。仅做 URL 预检不能防止 DNS 重绑定。任何答案含非公开地址或答案超过 64 个时，整个解析结果被拒绝。IP 字面量和重定向目标采用同一公开 IP 分类器，包括拒绝映射或 NAT64 嵌入的私有地址。不隐式采用环境代理；内部网络或代理访问须由宿主提供自定义 Driver，并自行确定传输政策。

这些检查是运行时门槛。运行不可信代码时仍需要操作系统或容器级隔离。
