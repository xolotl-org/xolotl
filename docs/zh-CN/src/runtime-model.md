# 运行时模型

Xolotl 只有一个主动实体：`Process`。

进程拥有已编译的句柄，针对资源发出操作并接收结果。宿主可显式选择 Fact 观察。文件、终端命令、推理、记忆、状态、远端设备和外部工具都通过同一套资源、接口、驱动和绑定模型进入运行时。

## 进程

进程携带：

- 身份；
- 生命周期状态；
- 授权记录和已编译句柄；
- 预算状态；
- 可选的终结器；
- 被另一个进程派生时形成的父子链接

派生会衰减授权范围。子进程权限由父进程授予的权限位限定。

### 预算

`BudgetSpec` 的 `max_micro_usd` 与 `max_inference_tokens` 是进程生命周期累计上限，`max_inflight_ops` 限制当前预留的操作数。`None` 不增加限制，零是有效上限。宿主原子地向调用者及全部祖先预扣，Driver 完成后结算实测用量；估算不足时实测仍可能超过上限。`restrict_budget` 取交集，不重置支出。分派前取消退还预留，分派后保留未确认消费；结束的 Future 释放并发槽。日历计费和跨执行的账户由宿主记账服务负责。

### 终结与请求所有权

`ProcessTable::finalization_report` 分享完成后的本轮清理报告：终态、来源、未决操作身份、类型化终结器失败及句柄释放计数。它独立于 Fact 记录。进程回收释放表的报告拥有；已取得报告的观察者自行管理留存。报告不恢复执行，也不保存完整调用历史。

`RequestProcess::finish(&output)` 在释放请求清理 pin 前返回不可变 `Arc<ProcessFinalizationReport>`。`RequestFinishError` 保留类型化 `source` 与原 `cleanup: CleanupTicket`；宿主保留 ticket，通过 `Bootstrap::resume_cleanup` 重试清理，不重跑正文。ticket 可以观察后来提交的报告，但报告或暂存未决身份本身不证明清理完成。`CleanupWaitExpired` 仅表示调用方观察期限已到，不证明清理停止或效果回滚。

SDK 的 `run*` 入口返回 `ExecutionCompletion`：通过 `output` 访问正文，通过 `finalization` 访问清理证据；只有准备阶段在接纳 Process 前拒绝时，后者才为 `None`。保留报告不会 pin 进程，也不会让表条目继续存活。

共同子进程准入自动回收符合条件的终态条目。根、仍有清理 custody、活动任务／终结器、预留操作、观察 pin 或子成员的条目继续保留。Tree 清理在等待前 pin 已选成员。不启动后台 reaper，pin 丢弃时也不立即回收；闲置终态条目可保留至后续准入。检查成本与容量规则见[核心与可移植程序](core-and-portable.md#资源与取消边界)。

`finalize_process` 在等待清理前关闭整棵树的子进程准入，中止任务并等待正文 Future 释放，然后先完成后代，再完成父进程。各进程反向运行终结器、撤销句柄并释放本轮资源；普通清理不写入持久状态标记。一个后代失败不妨碍其他后代清理，但父进程会保持待清理状态。已经完成的祖先仍可用于关闭其后代；尚无终结结果的活进程按取消处理。`finish_request_process` / `finish_process_as` 用于程序返回后结束指定进程，后者只接受终态。两者允许已独立启动的 Actor 和异步任务继续运行。正文或终结器尝试等待自己或包含自己的进程树时返回 `ProcessBusy`，需要先请求取消并返回控制权。终结上下文同时记录所属进程表和嵌套调用链，不同 Kernel 的相同编号可以独立使用。终结器可以完成其他空闲进程，但不会等待其他终结执行者，避免跨内核的循环等待。终结器失败时，保留失败详情并继续清理。SDK、Console 和 Gateway 入口创建的 request Process 会在程序返回后终结，包括失败和取消结果。终结期间，操作只允许访问当前进程的 `state://process/<process-id>/...` 子树，或调用接口元数据标记为可用于终结器的方法。

`Bootstrap::request_under` 返回的 `RequestProcess` 拥有请求生命周期。丢弃它立即取消请求树并撤销句柄，异步终结仍由宿主负责；`drain_cleanup` 重试调度失败、清理中断或后端失败留下的工作。SDK 请求入口遵循这一所有权约定，裸 Executor Future 则不拥有进程终结。`finish` 终结请求，`detach` 将责任交给宿主。

一次终结只能有一个执行者。终结 Future 被丢弃时会释放占用并唤醒其他调用者；尚未开始的终结器留在进程表中，已完成或已中断的尝试不会自动重放，中断会记为失败。重试保留首次选定的终态与待释放、待发布责任。进程终结器可以独立于原执行器继续运行，但已丢弃的执行 Future 无法运行程序内的词法 `Finally`。任务在进程表登记后才可开始正文；丢弃正文的退出通知在其捕获资源释放后发出。结果、终结意图和待发布对象在交出正文所有权前保留。Actor 目录和异步结果的发布错误会保留到 `drain_cleanup` 重试；不会重新运行驱动，也不会提前标记清理完成。重试保留原来的单进程或整树范围；一次单进程完成失败不会取消其独立子任务。完成后会释放原生模块、附着 grant、发布对象和终结器存储；终态条目与本轮报告保留到进程回收，业务数据和显式记录的 Fact 需要独立规划留存。

### Actor

Actor 是命名长寿 Process。`ActorSpec` 声明 body、能力上限、预算和终结器。启动 Actor 会检查 body 和终结器，创建普通 Process，附着衰减后的 grant，通过同一个 Executor 运行 body，并在 `state://agents/<identity>/<name>` 写入目录项供发现。body 或终结器引用 `StepRef` 时，宿主在启动时提供共享的不可变 `StepModule`。普通请求也能附着同一种模块，无需创建 Actor。Actor 声明可以在 body、终结器和 declared capabilities 中使用 `state://process/self/...`；启动时会在 lint、grant planning 和执行前绑定为具体 Process id。普通请求的授权模板也在权限衰减前绑定同一占位符。Step 引用自身只携带名称和参数。动态返回子图中的结构化操作与信号路径也会在编译前绑定到调用进程，包括嵌套恢复与清理子图。

Actor 目录写入也是受管任务的一部分，启动调用被取消或父进程关闭时会停止准入。终态目录只通过 CAS 更新相同进程、相同执行作用域的记录。失败准入可留下终态占位，防止迟到的初始写入重新发布 running 状态；冲突的现有 Actor 不受影响。

### 异步子进程

`AsyncProcess` 要求在 `KernelBuilder`、DataPlane 或 Executor 上显式安装 `host::async_process::AsyncProcessHost`。宿主在子任务调用 Driver 前预留所有权，并返回自定义 Value 引用；内核不再写默认结果路径。方法权限与 `SPAWN_WITH` 分别检查，子任务只得到单方法、无传播权限的衰减句柄。宿主选择配额、准备检查、取消来源及结果存储。

`admit` 是异步接口，宿主可以等待存储或容量，等待受父执行原始截止时间和取消信号约束。等待期间不创建子进程或派生句柄；返回后重新检查期限、父进程状态及传播权限，核对既有接受凭据也不例外。预留容量后，宿主应跨 await 持有 `AsyncProcessAdmission` 守卫。调用被丢弃、出错或 panic 时，未交接的守卫通过 `rejected` 释放预留；远程清理及结果不明的存储写入仍须由宿主监督器负责。内核接纳进程后，清理由终态发布负责，即使随后任务挂接失败也不会再调用拒绝钩子。准入期间不得运行子任务 Operation。

包括幂等方法在内，每次进程接受都经过宿主。方法缓存只保留主体结果，不缓存进程引用。宿主保留相同来源与授权的接受记录，且未完成任务及清理仍由原所有者负责时，可以返回 `AsyncProcessAdmission::already_accepted`；候选进程 ID 不进入进程表，不创建新任务，也不重复调用所有者钩子。权限、策略与截止时间检查仍生效。宿主须区分未确认预留和已接受凭据，并在来源仍可能重放期间保留后者。

子任务继承原始截止时间，宿主只能缩短期限。`publish` 在句柄释放和必需的 State 提交后接收已知结果及 taint；失败保留相同结果供收尾重试。`released` 确认受管任务的捕获已全部释放，并通知已知结果；主体被强制丢弃时传入 `None`。尚未成功发布时，清理仍保持未完成。保存引用本身不构成持久子任务恢复。

## 资源与接口

资源是被操作、授权、审计并绑定到驱动的被动对象。接口描述可用方法、输出模式、纯度、成本模型、模态支持和批处理支持。

数据路径通常使用资源 ID 和方法 ID。

## 驱动

驱动实现接口方法。它接收受限的 `DriverContext`、方法 ID、输入值、请求的输出模式，并返回结果。

驱动的授权来自受限的 `DriverContext`。如果驱动需要接触状态、发出流式片段、派生来源链或记录输出污点，它必须通过上下文暴露的运行时接口完成。

调用完成时保留驱动报告的来源顺序，再追加尚未包含的输入来源，成功和失败都遵循同一规则。portable、hosted、缓存完成和异步子进程结果共用这个规则。Fact 独立维护审计顺序，输入来源排在新增的输出观察之前。来源顺序不构成访问授权。

## 句柄

句柄是 `open()` 的已编译产物：资源、权限、快速路径模式、驱动计划、可选剩余策略、所属进程和世代号。

撤销会提升世代号，因此过期句柄 ID 会在复用前失败。

## 操作与事实记录

操作是发生副作用的唯一路径。它包含调用者、执行身份、句柄 ID、方法 ID、完整操作身份、输入值、输出模式和输入污点。Fact 共享完整的不可变输入与成功输出 Value，保留媒体元数据。

Fact 记录一次操作尝试。首次开始时分配追加位置，同一完整 ID 再次开始会复用该位置，完成时原地更新。媒体载荷用外部引用表示；内联字符串、列表、字节和 Fact 历史留存需要宿主分别限制大小。

显式选择 Fact 记录时，可信宿主在准入前固定观察一次调用进程的默认身份，写入 `Fact::caller_identity`。托管执行以进程表为准；portable 或无表宿主显式提供 `Some(identity)`，未知则保留 `None`。该基线不同于调用进程编号，也不同于本次选定的 `acting`。同一次调用的 pending、完成和拒绝复用准入快照；新的调用命中幂等缓存时记录自己的基线，不继承生产者的身份。`CrossIdentity` 只比较已知基线与 acting，包括 root；它表达身份切换尝试，不证明委托权限。网关审计 Fact 的两个身份都取 root。v1 必填可空字段与投影规则见[事实记录](state-and-facts.md#事实记录)。

`DataPlane::execute` 和 `execute_with_stream` 返回 `InvocationResult`，保留驱动结果及本轮未决效果身份。无法确认效果时报告 `OutcomeUnknown`，由应用依据原操作身份核对；取消和本地结果丢失都不证明外部效果回滚。流和受管子进程遵循同一结论，不能把未确认效果报告为成功。Fact 是可选观察，不代替权限、预算与数据提交。
