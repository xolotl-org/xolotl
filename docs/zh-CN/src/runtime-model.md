# 运行时模型

Xolotl 只有一个主动实体：`Process`。

进程拥有已编译的句柄，针对资源发出操作，接收结果，并记录事实记录。文件、终端命令、推理、记忆、状态、远端设备和外部工具都通过同一套资源、接口、驱动和绑定模型进入运行时。

## 进程

进程携带：

- 身份；
- 生命周期状态；
- 授权记录和已编译句柄；
- 预算状态；
- 可选的终结器；
- 被另一个进程派生时形成的父子链接

派生会衰减授权范围。子进程权限由父进程授予的权限位限定。

`finalize_process` 在等待清理前关闭整棵树的子进程准入，中止任务并等待正文 Future 释放，然后先完成后代，
再完成父进程。各进程反向运行终结器、撤销句柄、记录 `ProcessFinalized` 事实记录，并写入
状态标记。一个后代失败不妨碍其他后代清理，但父进程会保持待清理状态。
已经完成的祖先仍可用于关闭其后代；尚无终结结果的活进程按取消处理。
`finish_request_process` / `finish_process_as` 用于程序返回后结束指定进程，后者只接受终态。
两者允许已独立启动的 Actor 和异步任务继续运行。正文或终结器尝试等待自己或包含自己的
进程树时返回 `ProcessBusy`，需要先请求取消并返回控制权。
终结上下文同时记录所属进程表和嵌套调用链，不同 Kernel 的相同编号可以独立使用。
终结器可以完成其他空闲进程，但不会等待其他终结执行者，避免跨内核的循环等待。
终结器失败时，生命周期事实记录会写入失败数量和详情，同时继续清理。SDK、Console 和 Gateway
入口创建的 request Process 会在程序返回后终结，包括失败和取消结果。终结期间，操作只允许访问
当前进程的 `state://process/<process-id>/...` 子树，或调用接口元数据标记为可用于终结器的方法。

`Bootstrap::request_under` 返回的 `RequestProcess` 拥有请求生命周期。丢弃它会立即取消请求树、
撤销现有句柄；处于 Tokio runtime 内时，再调度一次清理。没有 runtime，或清理任务中断、失败时，
由 `drain_cleanup` 完成待处理工作。SDK 的普通图执行和 prepared 执行使用这一所有权约定。
单独的 Executor Future 仍由宿主管理生命周期；SDK 持久化执行显式将所有权交给检查点恢复，
保留被中断的请求。

一次终结只能有一个执行者。终结 Future 被丢弃时会释放占用并唤醒其他调用者；尚未开始的终结器
留在进程表中，已完成或已中断的尝试不会自动重放，中断会记为失败。重试复用同一条生命周期事实。
进程终结器可以独立于原执行器继续运行，但已丢弃的执行 Future 无法运行程序内的词法 `Finally`。
任务在进程表登记后才可开始正文；丢弃正文的退出通知在其捕获资源释放后发出。
结果、终结意图和待发布对象在交出正文所有权前保留。Actor 目录和异步结果的发布错误
会保留到 `drain_cleanup` 重试；不会重新运行驱动，也不会提前标记清理完成。
重试保留原来的单进程或整树范围；一次单进程完成失败不会取消其独立子任务。
完成后会释放原生模块、附着 grant、发布对象和终结器存储；终态条目、状态标记与 Fact 仍被保留，
宿主需要另外规划历史留存。

Actor 是命名长寿 Process。`ActorSpec` 声明 body、能力上限、预算和终结器。
启动 Actor 会检查 body 和终结器，创建普通 Process，附着衰减后的 grant，通过同一个 Executor
运行 body，并在 `state://agents/<identity>/<name>` 写入目录项供发现。body 或终结器引用
`StepRef` 时，宿主在启动时提供共享的不可变 `StepModule`。普通请求也能附着同一种模块，
无需创建 Actor。Actor 声明可以在 body、终结器和 declared capabilities 中使用
`state://process/self/...`；启动时会在 lint、grant planning 和执行前绑定为具体 Process id。
普通请求的授权模板也在权限衰减前绑定同一占位符。
Step 引用自身只携带名称和参数。动态返回子图中的结构化操作与信号路径也会在编译前
绑定到调用进程，包括嵌套恢复与清理子图。

Actor 目录写入也是受管任务的一部分，启动调用被取消或父进程关闭时会停止准入。
终态目录只通过 CAS 更新相同进程、相同执行作用域的记录。失败准入可留下终态占位，
防止迟到的初始写入重新发布 running 状态；冲突的现有 Actor 不受影响。

`AsyncProcess` 返回可查询的 `proc://async/<process>/<execution>` 引用。
状态与结果位于 `state://kernel/async/<process>/<execution>/status` 和 `outcome`。
异步任务拥有派生句柄，并使用相同的任务归属、取消、生命周期 Fact 和终态发布协议。
初始状态写入失败时不调用驱动；结果和污点在终态发布失败后仍保留供重试。

## 资源与接口

资源是被操作、授权、审计并绑定到驱动的被动对象。接口描述可用方法、输出模式、纯度、成本模型、模态支持和批处理支持。

数据路径通常使用资源 ID 和方法 ID。

## 驱动

驱动实现接口方法。它接收受限的 `DriverContext`、方法 ID、输入值、请求的输出模式，并返回结果。

驱动的授权来自受限的 `DriverContext`。如果驱动需要接触状态、发出流式片段、派生来源链或记录输出污点，它必须通过上下文暴露的运行时接口完成。

调用完成时保留驱动报告的来源顺序，再追加尚未包含的输入来源，成功和失败都遵循同一规则。
portable、hosted、缓存完成和异步子进程结果共用这个规则。Fact 独立维护审计顺序，
输入来源排在新增的输出观察之前。来源顺序不构成访问授权。

## 句柄

句柄是 `open()` 的已编译产物：资源、权限、快速路径模式、驱动计划、可选剩余策略、所属进程和世代号。

撤销会提升世代号，因此过期句柄 ID 会在复用前失败。

## 操作与事实记录

操作是发生副作用的唯一路径。它包含调用者、执行身份、句柄 ID、方法 ID、完整操作身份、输入值、输出模式和输入污点。Fact 共享完整的不可变输入与成功输出 Value，保留媒体元数据。

Fact 记录一次操作尝试。首次开始时分配追加位置，同一完整 ID 再次开始会复用该位置，
完成时原地更新。媒体载荷用外部引用表示；内联字符串、列表、字节和 Fact 历史留存
需要宿主分别限制大小。
